# UX / feature flags — booking-tool Canvas App (out-of-audit-scope log)

**Date:** 2026-07-31 20:30 (Europe/London). Companion to `2026-07-31-app-audit.md` (same sync, same method).
These items are anti-good-UX or feature-scoped observations that fall OUTSIDE the bug/performance/state audit. Flagged only — no fixes designed, no priorities assigned beyond grouping.

## Accessibility (platform checker: 546 errors)

- **266 × missing tab stop** (`TabIndex` on interactive controls) — keyboard users cannot reach most buttons.
- **204 × focus not visible** (`FocusedBorderThickness` 0) — keyboard focus is invisible where it does land. Note `AppTheme.FocusedBorder` is literally `Color.Red` in both themes (App.pa.yaml:139/201) — looks like a debug value that was never replaced.
- **76 × missing accessible label** — icon buttons/images with no `AccessibleLabel`.
- Date arrows on Find say "Previous/Next day" even in Week mode where they jump 7 days.

## Dead or half-dead features visible to users

- **Profile notifications section:** all four toggles hardcoded `DisplayMode.Disabled`, while the dependent "reminder minutes" dropdown is still live — users can edit a setting whose master switch they can't touch. The caption label that would explain "coming soon" has blank text. Reads as broken.
- **"Book on behalf" and "Private booking" toggles in the wizard:** permanently disabled but still visible and still driving validation/payload. Same "looks broken" effect.
- **`btnReportProblem` on Profile:** styled as a primary action, `OnSelect: =false` — does nothing.
- **"View week" on Rooms:** permanently disabled placeholder button.
- **Timeline date picker (`dtpTLDate`):** exists but `Visible: =false` — users can only step day-by-day; no way to jump ahead.
- **Room-focus highlight on Find** (`gblFindFocusRoomID` from Home's "rooms now" overlay): highlight formula exists but effectively never fires; also never reset, so if it ever works it will be stale.
- **Wizard title never says "Edit booking"** — `ModalTitleText` input is unused; edit mode shows "New booking" with a "Save changes" button.

## Destructive actions & confirmations

- **"Release room" on Home:** one tap cancels a booking with no confirmation — and the button is visible for *future* bookings, where "Release" actually means "cancel".
- **"Extend 15m"** enabled for bookings that haven't started yet — semantically odd.
- Series-cancel confirmation is inconsistent: myBookings uses a two-button inline swap with no explanatory text; bookingDetail says "This can't be undone"; neither shows the occurrence count being cancelled.
- Leaving myBookings mid-confirmation and returning shows the destructive "Yes, cancel series" pre-armed (audit STATE-3).
- Booking a slot that clashes silently *writes* a `Status="Clash"` row and tells the user to go fix it in My Bookings — a surprising side effect of pressing "Book"; the toast points at My Bookings → Series but doesn't navigate there.
- "Slot no longer free" on edit closes the modal and discards everything the user typed — full re-entry required.

## Navigation / flow

- Rooms wipes search, filters, selected room, and timeline position on every entry — returning from a booking detail loses all browse context. Find resets date/view (but not capacity/equipment). myBookings resets nothing. No consistent policy.
- `mb2BtnRowCancel` ("Cancel") does exactly what tapping the row does — opens the detail modal; no cancel-specific step. Misleading affordance.
- Booked slots on the Find timeline are not tappable (no detail view); only free slots respond.
- Browse-path "Book" opens the wizard with blank times while the timeline path pre-fills — inconsistent entry states.
- No step indicator in the 3-step wizard ("Step 2 of 3"); the submitting progress bar can never actually appear (audit LOW).
- The 500-row truncation warning on Find fires *after* the user is already looking at silently truncated data.

## Theming / consistency (Carbon rebuild drift)

- **Dark mode is half-wired:** screen `Fill` hardcoded white on Home, Find, Profile, bookingDetail (`RGBA(255,255,255,1)`) — dark mode would flash/sit white behind transparent containers. `glbIsDarkMode` is set once to `false` and nothing toggles it (no theme switch UI).
- Suspected inverted condition: `glbSideNavIconStr = If(!glbIsDarkMode, "rgba(198,198,198,1)", "rgba(82,82,82,1)")` (App.pa.yaml:310–313) gives *light* icons in *light* mode and dark icons in dark mode — backwards on its face; unverifiable without rendering (flagged here rather than as a bug).
- Two design systems coexist: cpt_Modal_ uses radius-2 + Lato; myBookings/cpt_BookingDetailModal use radius-0 + IBM Plex Sans (Carbon); Shell_Header hardcodes hex colors in HTML ignoring dark mode; Profile avatar hardcodes IBM Plex Sans + `#f4f4f4`.
- Token bypasses: `FocusedBorderColor: =RGBA(15,98,254,1)` vs `ColorValue(AppTheme.Primary)` mixed on Home; `HoverColor: =ColorValue("#0043ce")` hardcoded; `LoadingSpinnerColor` is Fluent blue `RGBA(0,120,212,1)`, not the Carbon primary; capacity dropdown uses `AppTheme.ButtonDangerHover` (a danger token) for neutral selection.
- `ThemeHex` is a hand-maintained URL-encoded mirror of `AppTheme` with a "KEEP IN SYNC" comment — drift is a matter of time.
- Hour axis on Home's occupancy chart hardcodes "08"–"18" labels while segments derive from `DayStartHour`/`DayEndHour` — the axis will lie if the working day changes. Week-cell "free hours" on Find similarly trusts `Timeline_HoursPerDay` matching `Timeline_OpenHour/CloseHour`.
- `bdmValSeries` shows the raw stored token ("BiWeekly") instead of friendly text.

## Content / hardcoding

- `"AUSTIN HQ"` / `"Austin HQ"` hardcoded as the site name on Home and myBookings.
- `lblHDStatLine` fixed Width 340 with `Wrap: false` — truncates on long counts/locales.
- Occupancy gallery on Home: `ShowScrollbar: false` with fixed height — more than 6 rooms scroll invisibly with no affordance.
- Fixed-pixel label positions inside responsive tiles (Rooms `lblRoomsStripEnd` X=217) misplace at other WrapCounts; `conCancelZone` Height 180 vs `LayoutMaxHeight` 110 may clip the scope prompt on bookingDetail.
- "Now" indicators freeze while a screen stays open (no Timer by design) — misleading on a wall/kiosk display; worst on the Home progress bar which implies live motion.

## Privacy / production-readiness (feature-scoped)

- **Private-booking masking is cosmetic:** the mask (`"Busy"`) is applied client-side while the full booking data (title, owner) is present in `colBookings` on every client. Anyone with the app + dev tools sees private bookings. Real privacy needs server-side shaping.
- **Mock data still live in prod OnStart:** `colPeople` (fake people picker) and `colUserSettings` (fake settings store) seed from mock tables; the Profile settings UI reads/writes the mock. All correctly carry `PROD-REVERT` markers matching the contract — flagged because the *user-visible* settings page silently doesn't persist anything.
- Ownership comparison is done three different ways (`BookedByEmail <> Lower(User().Email)`, `BookedBy.Email = User().Email`, `BookedByEmail = Lower(User().Email)`) — one canonical `fnIsMine()` UDF would prevent the case-sensitivity mask bug noted in the audit (BUG-21).

## Feature gaps noticed in passing

- No way to book across an hour boundary from the Rooms timeline (also audit BUG-5 — the 90m/2h chips can never enable).
- No "jump to date" anywhere in the timeline surfaces; no week view (disabled placeholder).
- No notification/search behavior behind the shell header's search and bell icons beyond open/close state globals (`gblUI_SearchOpen`, `gblUI_NotifOpen`) — panels exist as state but no visible implementation on the audited screens.
- No occurrence-count preview before confirming a recurring booking beyond the step-2 hint (which is hidden exactly when the form becomes valid — audit LOW).
